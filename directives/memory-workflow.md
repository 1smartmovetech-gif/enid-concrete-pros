# Memory Workflow

Use this workflow when deciding where information belongs.

## Quick routing

- Put raw session notes in `memory/YYYY-MM-DD.md`
- Put durable distilled memory in `MEMORY.md`
- Put structured topics in `second-brain/`
- Put repeatable procedures in `directives/`

## Promote information when

Create or update a structured note if one of these is true:

- The topic will likely come up again
- The note benefits from backlinks and graph view
- The note has relationships to people, projects, or decisions
- The information is too detailed for `MEMORY.md` but too important to leave buried in a daily log

## Suggested note targets

### People
Use `second-brain/people/` for:
- personal preferences
- roles and relationships
- recurring collaborators
- communication context

### Projects
Use `second-brain/projects/` for:
- ongoing workstreams
- business efforts
- technical builds
- property/trading systems

### Areas
Use `second-brain/areas/` for:
- long-running domains of responsibility
- health, finances, systems, operations, home, etc.

### Decisions
Use `second-brain/decisions/` for:
- a choice that matters later
- tradeoffs that should be remembered
- architecture / workflow / tool decisions

## Maintenance rhythm

Weekly or every few days:
1. Review recent `memory/` files
2. Promote repeated topics into `second-brain/`
3. Distill key facts into `MEMORY.md`
4. Add links between related notes
5. Remove stale or duplicated information
