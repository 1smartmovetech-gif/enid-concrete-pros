# obsidian-memory-structure

## Decision
Adopt a structured Obsidian-friendly second-brain layer inside the OpenClaw workspace instead of relying only on `MEMORY.md` and daily logs.

## Why
- Better graph view and backlinks in Obsidian
- Better separation between raw logs, curated memory, and structured notes
- Easier long-term maintenance

## Tradeoffs
- More files to maintain
- Requires discipline about where information gets written

## Consequences
- Add `second-brain/`, `templates/`, and `directives/memory-workflow.md`
- Continue using `MEMORY.md` and `memory/YYYY-MM-DD.md`
